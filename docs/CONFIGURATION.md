# 配置与行为说明

[返回项目首页](../README.md)

原生 macOS 个人助手面板，使用 SwiftUI 构建中文界面。支持 macOS 14 及以上，当前构建为 Apple Silicon。只提供个人身份的群聊与私聊监听、自动回复；应用机器人及 Webhook 链路已移除。

## 使用

打开 `dist/DWS Assistant.app`。

1. 左下角展示当前已授权账号与组织，点击查看姓名、组织 ID 和用户 ID；未授权时点击「去登录」，由 DWS 官方设备授权流程打开授权页并等待结果。面板只使用当前账号，新增会话自动绑定，不提供多账号选择。授权成功后自动刷新账号，消息监听仍由服务开关控制。
2. 点击「添加群聊」或「添加联系人」打开搜索框，按群名或姓名搜索，点击结果进入配置并保存。面板自动带入稳定群 ID 或联系人 `openDingTalkId`；名称使用官方搜索结果，不提供本地改名。
3. 点击会话的「配置」，在「监听配置」中开启监听后显示自动回复开关；开启自动回复后再显示触发方式、AI 标签、状态表情、引擎、模型和执行权限。关闭开关会收起相关配置并保留已有值。群聊默认「仅自己 @自己 回复」，也可选择「仅 @自己 回复」或「收到消息自动回复」；只识别真实 @ 事件，私聊按联系人独立配置。已有会话的触发方式保留。
4. 打开左下角「DWS助手服务」。会话卡片横向排列，最右侧为独立监听开关，配置与删除按钮直接展示；运行中切换只影响对应会话。保存会话配置也仅重新连接受影响的监听。

关闭主窗口后隐藏 Dock 图标，保留菜单栏和当前助手服务；从快捷栏重新打开主面板时恢复 Dock 图标。最小化主窗口不隐藏 Dock，独立快捷面板的开关也不影响 Dock 显示。快捷栏右上角显示版本，左下角提供文字按钮「打开主面板」；侧栏账号信息展示姓名与组织，不显示头像。快捷栏独立初始化账号与共享服务，主窗口关闭后仍可切换助手服务、查看监听中/处理中/本次已回复数量和最近动态，点击页面入口时才打开主面板；错误直接显示在快捷栏中，不会弹出已关闭的主窗口。也可从「窗口 → 快捷面板」或应用内快捷键 `⇧⌘D` 唤起独立小窗。打开应用或登录成功都不会自动开启服务。退出应用时先停止个人监听及正在处理的回复，清理完成后再退出；停止期间重复退出不会再次触发清理，停止失败则保留应用并允许重试。

## 外观与语言

「设置 → 界面语言」提供简体中文和 English，默认简体中文；登录页也可切换，选择会自动保存。旧配置中的跟随系统语言选项会迁移为简体中文。

「设置 → 外观」提供跟随系统、浅色、深色三种主题，立即应用到侧栏、内容、原生控件与弹窗；偏好保存在 `~/.dws-dashboard/config.json`，切换主题不停止监听。

图标统一使用矢量路径：下载的参考 SVG 保存在 `Assets/Icons/Original`，线宽统一后的源文件在 `Assets/Icons`，通过 `scripts/make-ui-icons.py` 生成 SwiftUI 路径。侧栏、概览、会话列表、搜索结果、空状态与顶部标题共用同一组件。

DWS Assistant Logo 使用字母 D、对话尾角和 AI 星芒；矢量源文件及横向字标位于 `Assets/Brand`，应用、侧栏和菜单栏共用同一图形。配色参考用户提供的官方图片，采用海军蓝、蓝紫与青蓝，并提供浅色对应色板。

## 回复设置

面板的程序控制与引擎实际权限优先于自定义规则。监听、触发方式、发送对象、回复形式及超时由程序决定；模型、强度与执行权限通过引擎参数或接口设置。自定义规则用于回复约定与任务步骤，不能覆盖这些配置。规则与默认文字提示、或多条规则之间，目前没有固定的冲突裁决顺序；发送者身份限制应在触发方式中设置。示例见 [设置与规则的优先级](../README.md#设置与规则的优先级)。

- **回复触发方式**（群聊）：新会话默认「仅自己 @自己 回复」，只有当前登录账号本人发出的真实自我 @ 消息才触发；「仅 @自己 回复」允许他人或本人 @当前登录账号；「收到消息自动回复」响应他人消息及本人手动 @自己。本人普通消息、缺少发送者的事件和助手自身回复均不会触发。发送者按已核验的 openDingTalkId 判断，不按昵称或正文匹配。旧配置保存的方式保留；私聊仍按联系人自动回复。

- **自定义规则**：在会话配置的「AI 回复设置 → 自定义规则」打开规则列表，列表仅展示名称和内容，右侧可开启、编辑和删除；新增或编辑均在独立弹窗中进行，保存后更新列表，取消不修改规则。也可点击「从其他会话克隆」，选择当前账号下其他群聊或私聊的规则；保留名称、内容及开关状态，并创建独立副本，后续修改互不影响。只复制规则，不复制目录与执行权限。点击列表的「完成」后再保存会话配置。规则仅用于当前会话，支持 Codex、Claude Code、Qoder 和 Gemini。例如约定“收到打包请求时，执行授权项目中的 scripts/build.sh 并报告结果”。规则由 AI 结合当前请求理解，不是面板直接运行脚本；仍受授权目录与执行权限约束。规则条数不限，每条内容最多 2,000 字；仅将已开启的规则传给引擎。Codex 继续使用当前会话，并在下一轮应用最新规则；Claude/Qoder 仍按有效规则隔离上下文。

- **回复形式**：每个群聊与私聊可选择普通文本、Markdown 或 AI 卡片，旧配置默认普通文本。Markdown 支持标题、列表、代码等文字排版，图片语法转为链接，避免自动上传本机附件。AI 卡片使用 DWS 自带的 A2UI 能力；开始处理消息时先创建动态处理卡片，取得服务端卡片 ID 后再调用 AI；读取图片、生成结果和已知失败在同一卡片更新，结果不确定时停止更新，不重建卡片。普通答复展示 Markdown，需要确认、选择或补充文字时由 AI 提供受限的表单定义，宿主构造组件和按钮。无需另装卡片工具，当前展示实际处理阶段与最终结果，暂不逐字流式输出。
- **交互卡片**：监听官方 `user_card_action_triggered` 个人事件，兼容原生 `a2uiEvent.action` 及旧版 `actionData.context` 回调。原生回调的 `operatorDTO.openDingTalkId` 必须匹配启动时核验的当前账号。使用当前钉钉账号操作并保持助手服务开启。支持确认/取消、单选、多选与文字输入；确认按钮保持高亮，点击时读取最新输入并校验必填项；未填完整时提示补充且不提交，宿主收到回调后再次校验，取消始终可用。钉钉的禁用状态只支持固定值，不再通过两个按钮的动态显隐模拟输入联动，以免填写或选择后仍然无法提交；确认后继续同一会话任务，结果更新原卡片，不另发一条消息。点击不会扩大授权目录或执行权限。卡片绑定账号、会话、服务端 bizId、随机交互标识与创建时配置，默认等待 60 秒，可在会话配置的「回复形式 → AI 卡片 → 卡片等待超时」直接输入或步进调整（10–86400 秒），独立于 AI 单次执行超时，保存后用于新卡片；助手运行时按到期时间检查并关闭过期且未操作的卡片，收起选项与按钮并显示「已过期，未执行任务」，不调用 AI。应用关闭期间过期的卡片在重新开启服务后补更新；更新结果不确定时不自动重试。修改会话配置后旧表单失效。选项标签取自本地定义，重复提交仅处理一次；取消不调用 AI，停止服务或更新结果不确定时不自动重试。多轮补充沿用原卡片，每轮使用新的交互标识。字段无法解析时记录原因，不静默忽略，也不将原始回调正文写入活动日志。
- **AI 卡片回执**：创建前持久化请求内容与目标，取得服务端 bizId 后保存更新引用。接口接受与客户端展示分开记录；当前接受成功显示「卡片已提交，展示待确认」，不计入已确认回复，原消息使用「迷惑」。创建或更新结果不确定时不重新创建、不改发普通消息；本机留存记录供排查。开发验证使用模拟 CLI 和官方离线 lint，尚未向真实会话发送卡片验证客户端展示。
- **AI 标签**：普通文本与 Markdown 可独立控制 AI 角标，默认开启，通过官方 `--ai-tag=true/false` 生效。A2UI 接口不提供该参数，选择 AI 卡片时隐藏角标开关，并保留原偏好供切回普通消息时使用。AI 卡片在处理、结果、交互、取消、过期与失败状态的底部统一展示 `「此消息由DWS助手通过DWS CLI自动回复」`。
- **卡片执行进度**：Codex 按实际开始与结束事件，在原卡片中分组展示 DWS 操作、命令、工具、搜索及文件修改；可展开查看各步骤状态。其他引擎继续展示处理阶段与结果。失败、取消或未报告结果的步骤不会标成成功；不转发内部推理、命令正文、参数和工具返回内容，每轮最多保留 128 项。进度更新合并发送，最终结果会等当前更新结束后再替换，防止晚到的进度覆盖结果；更新结果不确定时停止本次任务，不重试或创建第二张卡片。
- **操作倒计时**：交互卡片先展示「提交后继续处理，结果更新在此卡片。」，下方使用钉钉原生 `Countdown` 显示「请在 … 内操作！」。倒计时使用与提交校验一致的绝对截止时间，在客户端持续更新，不反复写入表单或清空选项；数字及单位的格式由钉钉客户端渲染。旧客户端不支持该组件时显示截止时间。确认被接受后，任务使用 AI 执行超时，不再受表单等待时限影响。旧卡片不会主动重发，新一轮卡片使用此布局。
- **状态表情**：默认开启，在触发回复的原消息上使用官方表情名称「思考」表示处理中，「对勾」表示已确认回复，「打叉」表示生成失败；投递未知使用「迷惑」。处理结束移除「思考」，主动停止只清理处理中标记。表情与 AI 生成并行，不阻塞正文发送；接口失败写入日志，不改变投递结果。缺少原会话 ID 时跳过表情，不猜测私聊会话 ID。
- **模型与思考强度**：Codex 通过 `model/list` 和 `config/read` 读取实际选项与默认值；Claude Code 通过初始化元数据读取模型及各模型支持的强度。只查询元数据，不创建 AI 推理任务。Qoder 尝试 `--list-models`，未登录或旧版本无法解析时明确提示；Gemini 读取本机模型配置，保留手动输入。仅对支持的模型展示返回的强度值。
- **授权目录**：默认留空，可多选并移除全部目录；旧配置自动带入的用户主目录会清除。空列表时，引擎从应用数据目录下的独立工作目录启动，不再默认进入用户主目录。有选择时从首项目录启动，其余按引擎原生参数传入。Codex 使用子进程 `sandbox_workspace_write.writable_roots`（只读模式仍保持只读）；Claude/Qoder 使用 `--add-dir`，Gemini 使用 `--include-directories`。目录列表不构成严格文件读取沙箱，实际访问范围仍受引擎原生权限控制。Codex 的目录和模型变化在原会话下一轮生效，其他引擎仍按配置隔离会话；不修改引擎全局配置。界面内属于当前用户主目录的路径统一缩写为 `~`，存储和调用保留绝对路径。
- **项目读取与执行**：Codex 按面板的明确目录授权接收项目任务指令，不继承上游群机器人“仅分析聊天附件”的限制。受限模式可查看项目、搜索打包脚本及执行只读查询；构建、修改文件等写入操作仍受只读沙箱限制，添加目录不会自动开启写权限。更新后使用新的 Codex 会话命名空间，避免旧会话的附件限制继续生效；后续仍按会话恢复上下文。
- **任务执行与回复**：具体任务由所选 AI 引擎结合当前请求和已开启规则处理，面板不预设打包或脚本流程，也不根据脚本内容增加审查或拦截。宿主负责将本次自动回复和卡片更新发回当前会话，避免重复发送；这一要求不禁止任务本身明确要求的上传、发布或通知。目录授权、实际执行权限和超时仍由面板与引擎控制。
- **Codex 会话**：使用 `~/.dws-dashboard/codex/` 独立存储会话、数据库、日志和写入锁，与桌面 Codex 各自维护上下文。首次回复创建新会话，不读取、接续或迁移旧会话及旧绑定。之后按当前账号及群聊/私聊稳定 ID 固定绑定，模型、思考强度、执行超时、目录、权限、规则和名称变化不新建会话；下一轮恢复时传入当前配置及授权范围。切回“跟随引擎”时读取当前默认值。若本应用的记录被删除或丢失，仅在 Codex 明确返回“找不到该会话记录”、尚未开始执行时重建一次，并在日志说明历史上下文不可恢复；登录、网络、执行失败及结果不确定都不会重跑任务。恢复接口返回的实际会话 ID 在执行前保存，保存失败则不执行。日志仅记录创建/续用/重建及脱敏短标识，不记录原始协议或消息正文。
- **Codex 会话历史**：群聊和私聊的 Codex 条目在「配置」旁提供「会话历史」入口，查看当前绑定的用户消息、AI 回复及执行记录，支持刷新、加载更早记录和展开执行详情。查看时只读取本应用的记录文件，不启动 AI、不占用会话写入锁。内部指令和推理记录不展示。首次使用前显示空状态，不回退到桌面端历史。
- **Codex 会话名称**：在「AI 回复设置」中可填写，留空默认“DWS · 群聊 · 群名”或“DWS · 私聊 · 联系人”；下次回复时同步到专用存储中的 Codex 会话，名称同步失败不丢弃已生成答复。钉钉名称保持官方原值。新会话不会出现在使用默认存储的桌面 Codex 最近会话或项目列表中；原有桌面记录保留，不再由本应用接续。
- **耗时**：日志分别显示 AI 生成与发送耗时，卡片显示最近一次回复耗时；面板区分 AI 生成中、发送中、监听中及待开启助手服务。

## 官方 AI 适配复用

个人收发调用已安装的 `dws event` 和 `dws chat +messages-send --as user`。Codex、Claude Code、Qoder 直接复用固定版本 DWS 的 `newLocalAgentForwarder`、官方协议解析及会话恢复，没有维护另一套 CLI 协议。

上游为 **DWS v1.0.66**，提交 `f215043e676d6889e1ddce3464828d8b1ec40c31`。构建下载并核验源码 SHA-256，在原模块内部添加薄包装层。Codex 的会话级思考选项通过官方进程创建钩子及恢复参数传入；会话生命周期复用官方客户端、最终回复解析和附件处理，增加固定绑定、明确缺失时恢复及官方 `thread/name/set` 命名，Claude/Qoder 使用各自的会话级参数；Claude 移除适配层的历史固定模型，读取本机模型与强度设置后按进程传入。上游适配器源码保持原样。

Gemini 使用本机 CLI 登录与 JSON 最终回复，单轮调用。固定版本 DWS 原生 Gemini 使用 API Key，因此没有切换到该 API 通道。

## 本地数据

应用配置、日志和会话缓存统一放在 `~/.dws-dashboard`：

- `config.json`：会话与本机调用设置，原子写入，权限 0600。
- `activity.json`：最近 500 条脱敏状态日志，不记录个人消息正文。
- `delivery-ledger.json`：个人回复意图、去重与投递状态；AI 卡片额外留存创建内容、更新引用、表单定义及是否已处理，提交与占用记录原子保存，重启不会重复执行。普通消息不保存正文。未知结果不会自动重发。
- `agent-sessions`：官方适配器会话映射；Codex 使用新的绑定命名空间，按账号及会话固定绑定，其他引擎仍按 AI 设置隔离。
- `codex`：钉钉专用 Codex 原生会话、索引数据库、运行日志及写入锁。通过子进程 `CODEX_HOME`、`CODEX_SQLITE_HOME` 和存储配置覆盖固定到此目录，与授权项目目录无关。仅链接本机 Codex 的配置、登录文件及规则/技能等输入，不复制旧会话、不共享桌面端数据库或写入锁。删除这里的记录会丢失钉钉会话的上下文。其他 AI CLI 仍使用各自的原生存储。
- `engine-metadata`：模型查询子进程的运行缓存，不保存登录凭据。
- `bin`：指向已安装引擎的本地调用别名，不移动或修改原安装文件。

首次打开新版时，从 `~/Library/Application Support/DWS Dashboard` 原子复制个人配置、日志、投递账本及会话映射；原目录保留。目标目录已存在时不覆盖。旧版仍运行时会阻止迁移，需先退出旧版。旧配置中已移除的机器人字段不再加载或执行。

DWS 和 AI 引擎使用用户已有的安装位置与登录状态。面板不会迁移它们的安装或授权目录。登录 macOS 时打开面板使用系统 SMAppService，需用户主动开启。

## 行为边界

- 仅消息接收事件会触发回复，reaction/read/recall 不会触发。每个会话可设置只监听。
- 全局停止与单会话关闭都会取消对应生成任务；发送前再次核对当前配置。重复事件、跨重启事件和未知投递不会重复发送。
- 启动前按当前账号的 userId 精确核验发送者 openDingTalkId；核验失败时不启动监听。本人普通消息和缺少发送者的事件不会触发 AI。真实手动 @自己可触发；选择「仅自己 @自己 回复」时，他人的 @ 消息也不会触发。发送前记录回复指纹，取得回执后记录消息 ID，并在出队时复核，避免助手回复回流早于回执造成循环。此保护不依赖 AI 角标；指纹与发送 ID 都按账号、会话隔离，不保存普通回复正文。
- 同一账号的群 @ 通道由开启自动回复的群共享，包括“收到消息自动回复”，以接收手动 @自己；关闭一个群不会停掉其他群的 @ 监听。
- 状态表情使用事件的准确会话和消息 ID、明确账号，不根据展示名搜索目标。正常退出会等待表情清理；异常崩溃或远端拒绝请求时可能保留旧标记，日志会记录可观察到的失败。
- 授权目录不等于完整文件访问沙箱。Codex 受限执行为只读、宽松为工作区可写；其他引擎沿用官方权限语义。
- 支持当前消息及同一会话引用消息中的图片：先按准确消息 ID 获取资源元数据，再通过 DWS 官方下载命令取回图片，校验实际文件并转换为最长边 2048 像素的 JPEG，动画取首帧。Codex 使用原生 `localImage`，Claude 使用附件读取权限，Qoder 使用 `--attachment`，Gemini CLI 使用 `@` 图片引用；识别能力取决于所选模型。语音、视频及其他文件暂不解析。
- 图片临时缓存位于 `~/.dws-dashboard/image-cache`。总额度 64 MiB（包含下载文件与转换文件），单张下载硬限制 8 MiB，每条最多 4 张；通过进程文件大小限制约束下载中的临时文件，不仅检查下载后的大小。结束、失败或取消均删除本次文件，异常退出的残留在下次启动清理。缓存满时停止本次图片处理，不淘汰仍被其他会话使用的图片。
- 组织策略禁止订阅或下载时显示错误，不改用历史轮询或猜测资源 ID 绕过。

## 安装与登录

每次启动都检测 DWS 安装及当前账号的授权登录状态；无论是否完成过首次引导，未安装、未登录或状态无法确认时都停留在前置页，快捷面板也不能启动服务。首次引导完成标记仅用于欢迎流程，不能绕过账号检查。AI 引擎仅检查是否安装，可稍后配置，不将“检测到程序”视为已登录。设置中不再提供独立的环境检查按钮或弹窗。

运行期间监听 `~/.dws` 和 `~/Library/Application Support/dws-cli` 中账号索引及授权文件的变化，仅观察文件元数据，不读取凭据正文。执行本机 `dws auth logout` 后，文件变化立即触发只读核验（合并 150 ms 内的连续写入），发现退登就停止助手、返回登录页；切回应用时也立即检查，并每 30 秒兜底检查。它不是钉钉服务端推送，实际响应还受 CLI 检查耗时影响。侧栏始终显示已登录账号，点击可查看详情或退出登录。面板退出只针对当前 `corpId:userId`，先停止助手，再调用官方 `auth logout --profile`；保留全部会话配置，重新登录不会自动重启服务。

授权检查使用 `dws auth status --readonly --format json`，不修改凭据。按照 [DWS 官方登录状态语义](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli#multiple-organizations-profiles)，可续期的登录态仍视为已授权；读取失败、需要修复及不完整账号信息显示为待检查，不误报为已退出或自动重新授权。此检查不代表网络、组织策略及所有接口权限均已通过。
